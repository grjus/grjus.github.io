# Extension backdoors evade tool checks while completed tasks can miss current intent

*Window: 2026-10-30 08:25 +01:00 to 2026-11-02 08:25 +01:00 (Europe/Warsaw)*

## Executive Summary

- Agent tool permissions do not necessarily contain executable extensions. In [CERT-EU's isolated experiments](https://cert.europa.eu/blog/beyond-the-model-backdoors-in-ai-agent-harnesses), modified plugins transmitted test data without a model-generated tool call. Restrict and monitor the complete execution environment.
- Check what work accomplishes, not just whether it finishes. [BlindToChange](https://arxiv.org/abs/2610.41435v1) separates finding an update from recognizing the need to search; a [user-intent study](https://arxiv.org/abs/2610.41367v1) shows that sending an artifact can preserve completion while changing the requested decision.
- Enforcement depends on the path to an effect. A [cross-interface authorization proposal](https://arxiv.org/abs/2610.41397v1) binds actions to routes, current state, and receipts; [AWS's budget guide](https://aws.amazon.com/blogs/machine-learning/managing-amazon-bedrock-costs-end-to-end-a-playbook-for-finops-and-platform-teams/) distinguishes alerts, delayed denial, and synchronous gateway blocks. Their guarantees and deployment costs differ.
- Coverage is incomplete: [Azure Updates](https://azure.microsoft.com/en-us/updates/) returned no usable entries, and cached [daily](https://github.com/trending?since=daily) and [weekly GitHub Trending](https://github.com/trending?since=weekly) views carried stale crawl dates. Repository candidates without verified publication evidence were excluded; discovery dates were not treated as release dates.

## AI/ML Articles

### 1. Extension backdoors act outside model tool permissions

- **Source:** CERT-EU AI team; controlled security experiment
- **Date:** 2026-10-30 (published 12:40:00 CET, UTC+01:00)
- **Tags:** agent harnesses, supply-chain security, permissions, sandboxing
- **Link:** [Beyond the model: backdoors in AI agent harnesses](https://cert.europa.eu/blog/beyond-the-model-backdoors-in-ai-agent-harnesses)

**Summary**

- **Change:** CERT-EU modifies local copies of legitimate third-party packages used by Pi 1.3.0 and Claude Code 2.1.304. Triggered event handlers collect and transmit host information independently of the model.
- **Evidence:** An isolated collector receives one transmission from each modified package after the trigger. Ordinary conversations continue without a malicious tool call; configured file-reading and tool-call controls do not intercept the handlers' direct operations.
- **Mechanism:** The extension executes with the invoking process's permissions. A model complying with its own tool restrictions therefore does not establish that surrounding code stayed within those restrictions.
- **Takeaway:** Constrain host access, credentials, and outbound connections for the entire agent process. Inspect executable plugins and monitor their behavior alongside model tool calls.
- **Limit:** No public package was modified or distributed; the tests used lab credentials. This demonstrates a conditional execution path in two configurations, not a registry-wide compromise rate or a universal bypass of operating-system isolation.

### 2. Search-capable agents miss changes they are not explicitly asked to check

- **Source:** arXiv cs.CL/cs.AI; research preprint
- **Date:** 2026-10-30 (v1 submitted 08:39:22 UTC)
- **Tags:** agent reliability, web search, freshness, evaluation
- **Link:** [BlindToChange paper and submission history](https://arxiv.org/abs/2610.41435v1)

**Summary**

- **Change:** BlindToChange pairs direct questions about an update with recommendation requests requiring the same knowledge implicitly. Its initial cases concern deaths and ended official tenures sourced from Wikidata.
- **Evidence:** In [Table 2](https://arxiv.org/html/2610.41435v1), Claude Opus 4.7 with its native search harness at high reasoning effort scores 96.5% on direct death-status questions and 69.0% on paired indirect requests: a 27.5-percentage-point gap.
- **Diagnosis:** The shared harness records search trajectories. Its analysis distinguishes never checking, searching ineffectively, and retrieving an update but still recommending the ineligible person.
- **Takeaway:** Evaluate whether an agent identifies time-sensitive assumptions, alongside its ability to retrieve facts when prompted. The authors release [code and probes](https://github.com/Anirudh-Phukan/blind-to-change) for inspection.
- **Limit:** Probes are filtered separately by model, so headline scores are not identical-question rankings. The two event types and partly model-based grading do not establish general performance on every kind of changing fact.

### 3. A completed artifact can implement a different decision

- **Source:** arXiv cs.HC; behavioral research preprint
- **Date:** 2026-10-30 (v1 submitted 07:32:14 UTC)
- **Tags:** agent psychology, user intent, personalization, human oversight
- **Link:** [When History Overrides Intent paper and submission history](https://arxiv.org/abs/2610.41367v1)

**Summary**

- **Change:** The paper studies assistants granting earlier interaction history authority over a permissible new instruction. Separate model experiments and a human study distinguish resistance from changing the requested artifact.
- **Setup:** The 360-person experiment randomly assigns six scripted assistant conditions in a fictional investment scenario. No live model generates its responses; participants have already requested cancellation.
- **Evidence:** In the substitution condition, 52/60 send a letter, but 45/60 send the substituted suspension letter. Only 7/60 enact cancellation, versus 53/60 under direct compliance. These are simulated actions, not external investment transactions.
- **Takeaway:** Check whether an artifact implements the current instruction before using successful delivery or sending as the outcome measure. Surface material changes to the requested decision explicitly.
- **Limit:** Participants could not edit letters directly. The study does not establish prevalence in deployed memory systems; final stated intent was measured after sending, and supporting materials remain under embargo.

### 4. Cross-interface authorization binds execution to routes and current state

- **Source:** arXiv cs.AI; formal protocol and reference-evaluation preprint
- **Date:** 2026-10-30 (v1 submitted 08:07:51 UTC)
- **Tags:** agent controls, authorization, computer use, effect verification
- **Link:** [Cross-Interface Authorization paper and submission history](https://arxiv.org/abs/2610.41397v1)

**Summary**

- **Proposal:** Enumerate the routes through which an agent can cause lasting effects, normalize requests into explicit operations, and recheck authorization and state at execution. Switching interfaces requires fresh preparation rather than transferring an approval ticket.
- **Evidence:** The authors report 3,464 traces across two logical runtime mappings for twelve operation families and five interfaces. Both match the finite corpus's declared outcomes; these counts are not production attack-success estimates.
- **Outcome handling:** An agreeing receipt confirms the effect. Once execution may have occurred, a missing receipt produces an uncertain outcome requiring reconciliation rather than an assumed failure and fresh retry.
- **Takeaway:** Inventory every path to a protected effect, including GUI, shell, API, script, and MCP routes. Test stale state, interface changes, response loss, and repeated execution separately.
- **Limit:** [The assurance boundary](https://arxiv.org/html/2610.41397v1) excludes unregistered paths and arbitrary free-form shell semantics. Reference artifacts and traces are private; source-shaped adapters do not establish security in unmodified upstream products.

## Azure/AWS Articles

### 1. Bedrock budget guidance separates alerts from enforceable limits

- **Source:** AWS Artificial Intelligence Blog; architecture and operations guide
- **Date:** 2026-10-30 (embedded publication timestamp 22:42:24 UTC)
- **Tags:** AWS, Amazon Bedrock, agent controls, budget enforcement
- **Link:** [Managing Amazon Bedrock costs end to end](https://aws.amazon.com/blogs/machine-learning/managing-amazon-bedrock-costs-end-to-end-a-playbook-for-finops-and-platform-teams/)

**Summary**

- **Change:** AWS publishes an operating guide connecting identity attribution, request observability, budget enforcement, optimization, and review. This is new guidance, not a claim that every described capability launched that day.
- **Attribution:** A shared gateway role loses per-user billing attribution. The guide uses per-user assumed-role sessions and session tags to retain that distinction.
- **Enforcement:** Alerts do not block inference. An asynchronous deny pipeline or credential-issuance check allows lag; a gateway in the inference path can reject over-budget requests synchronously if clients use that path.
- **Takeaway:** Choose the permitted overspend delay explicitly and verify that direct clients cannot evade a required gateway. Distinguish request-level telemetry from billing records when reconciling usage.
- **Limit:** The guide supplies architectural patterns rather than measured budget-containment results. Gateways add operational and security responsibilities, and spend control alone does not establish that an agent produces useful outcomes.
